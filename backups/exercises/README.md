# Снимки справочника упражнений

Здесь лежат выгрузки таблицы `exercises` — **вместе с `youtube_id`**.

## Чем это отличается от `exercises_seed.json` в корне

Двумя вещами, и путать их нельзя:

| | `exercises_seed.json` (корень) | файлы здесь |
|---|---|---|
| Что это | СЕМЯ для первичного наполнения пустой базы | СНИМОК живого справочника |
| `youtube_id` | **нет ни одного** | 852 из 873 |
| `video_status` | нет поля | 852 `unchecked`, 21 `no_video` — проставлены автоматически |
| Кто читает | приложение при старте, если таблица пуста | человек, вручную, при восстановлении |
| Структура | голый список | объект с полем `формат` и метаданными |

**Импортировать сюда seed нельзя** — `dump_exercises.py --restore` его отвергнет
по полю `формат` и объяснит разницу. Проверка стоит именно затем, чтобы
устаревшее семя не затёрло результат импорта видео.

## Зачем отдельно от общего архива

852 значения `youtube_id` — результат импорта, шедшего несколько дней
и упиравшегося во внешние ограничения. Из репозитория он не воспроизводится.

Общий архив базы (Telegram, ежедневно) этот слой защищает, но восстановление
из него возвращает базу **целиком** — то есть чинить справочник пришлось бы
ценой отката всех пользовательских данных за период. Файл отсюда
накатывается поверх живой базы и трогает только `exercises`.

## Как пользоваться

```bash
# Снять свежий снимок с прода
flyctl ssh console -a energydess-tools -C "sh -c 'cd /app && python dump_exercises.py --dump'"
MSYS_NO_PATHCONV=1 flyctl ssh sftp get /app/backups/exercises/exercises-ГГГГ-ММ-ДД.json \
  ./backups/exercises/exercises-ГГГГ-ММ-ДД.json -a energydess-tools
flyctl ssh console -a energydess-tools -C "rm -rf /app/backups"

# Посмотреть разницу с текущей базой, ничего не меняя
python dump_exercises.py --restore backups/exercises/exercises-ГГГГ-ММ-ДД.json --dry-run

# Накатить
python dump_exercises.py --restore backups/exercises/exercises-ГГГГ-ММ-ДД.json
```

Импорт **только добавляет и обновляет**: записи, которых нет в файле,
из базы не удаляются.

## Когда снимать новый

После любого пополнения видео или ручной модерации в админке — на сегодня
модерации не было, все 852 `youtube_id` проставил импорт. Ежедневно
не нужно — справочник меняется редко, а каждый снимок весит около 4 МБ
и остаётся в истории git навсегда.

Файлы **не попадают в образ приложения** (`backups/` в `.dockerignore`):
на машине им делать нечего, восстановление идёт с локального компьютера.

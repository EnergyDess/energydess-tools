# `_meta.html` — мета-теги, Open Graph, Twitter Card

Единственное место, где описаны теги превью. Раньше их не было вовсе: ссылка
на сайт разворачивалась в мессенджерах голым URL — ни заголовка, ни описания,
ни картинки. Критично, потому что ссылка уходит работодателям.

## Как подключать

В `<head>` страницы, после `meta charset` и `viewport`:

```jinja
{% set meta_tool = 'hh' %}
{% include '_meta.html' %}
```

Для страниц вне `TOOLS`:

```jinja
{% set meta_title = 'Профиль' %}
{% set meta_desc  = 'Необязательно — без него подставится общее описание' %}
{% include '_meta.html' %}
```

| Переменная | Назначение |
|---|---|
| `meta_tool` | id инструмента из `TOOLS`; имя и описание берутся оттуда |
| `meta_title` | заголовок без хвоста «— EnergyDess», он добавится сам |
| `meta_desc` | описание страницы; необязательно |

Не передав ничего, страница получит общий заголовок и описание сайта.

## Почему пояснение вынесено сюда, а не лежит комментарием в шаблоне

**Jinja не поддерживает вложенные комментарии, и последовательность из решётки
с закрывающей фигурной скобкой закрывает блок где угодно — даже внутри текста,
даже в кавычках.**

На этом дважды сломался прод:

1. В комментарии был пример вызова с собственным пояснением в скобках. Его
   закрывающая последовательность закрыла внешний комментарий, и пример
   `{% include '_meta.html' %}` стал настоящим кодом — получилась рекурсия
   на 958 уровней и 500 на всех страницах.
2. В переписанном комментарии осталось само упоминание этой последовательности
   в кавычках — как объяснение первой поломки. Комментарий снова закрылся
   досрочно, и весь оставшийся текст вывалился на страницы как обычный текст,
   причём **внутри `<head>`**.

Поэтому в шаблоне теперь одна строка-ссылка на этот файл, а всё пояснение —
здесь, в markdown, где ничего не парсится.

## Важные детали реализации

- `og:url` и `og:image` собираются от `BASE_URL` (глобал шаблонов, регистрируется
  в `main.py` рядом с `TOOLS`). **Абсолютный URL обязателен** — с относительным
  путём превью не собирается ни в одном мессенджере.
- `og:image` одна на весь сайт: `static/og.png`, 1200×630. Отдельных картинок
  под инструменты нет и не планируется.
- Тексты инструментов не дублируются: приходят из `TOOLS` в `main.py`. Добавление
  нового инструмента правки тегов не требует.
- Демо-страницы (`demo_landing.html`, `demo_program.html`) этот partial **не
  подключают** — у них свой `noindex`.
